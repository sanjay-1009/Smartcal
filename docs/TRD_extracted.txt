SMART CALENDAR

Technical Requirements Document (TRD)

Project Name: Smart CalendarVersion: 1.0Architecture: Client–Server REST ArchitectureBackend: Java + Spring BootFrontend: React + ViteDatabase: MySQL

1. Technical Overview

Smart Calendar will be developed as a web-based client-server application.

The frontend will provide the user interface and communicate with the backend through REST APIs.

The backend will handle:

Authentication

User management

Event management

AI processing

Web scraping

PDF processing

OCR

Conflict detection

Notification scheduling

MySQL will provide persistent storage.

17. Conflict Detection

The conflict detection module will compare the new event against existing events belonging to the same user.

For two events:

Event A:

StartA

EndA

Event B:

StartB

EndB

An overlap exists when:

StartA < EndB

AND

StartB < EndA

The system should check:

Same date

Overlapping time

Existing event status

For events without a specific time, the system can issue a date-level warning instead of claiming a time conflict.

20. API Security

Authenticated endpoints should require a valid JWT.

Example:

GET /api/events

The backend should determine the user from the authenticated token rather than trusting a user ID supplied by the frontend.

This prevents users from requesting another user's events.

31. Core Technical Principle

The central technical principle of Smart Calendar is:

Convert unstructured event information into structured, user-approved calendar data.

The system therefore follows:

UNSTRUCTURED INFORMATION

          ↓

      Extraction

          ↓

      AI Analysis

          ↓

STRUCTURED EVENT DATA

          ↓

   User Confirmation

          ↓

  Conflict Detection

          ↓

       Calendar

          ↓

     Notifications

This architecture keeps AI responsible for understanding information, while the backend remains responsible for validation, business logic, security, scheduling, and persistence.
